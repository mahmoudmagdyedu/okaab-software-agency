## 2025-05-24 - [CRITICAL] Prevent DoS by Checking Buffer.byteLength Before crypto.timingSafeEqual
**Vulnerability:** The application used `crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(supplied))` after only verifying that `expected.length === supplied.length` on the original strings. If `supplied` contained multi-byte characters, `Buffer.from(supplied).length` would differ from `Buffer.from(expected).length`, despite having the same string length. Node.js throws an unhandled `ERR_CRYPTO_TIMING_SAFE_EQUAL_LENGTH` exception when `timingSafeEqual` receives buffers of different sizes, allowing an attacker to easily crash the Node server (Denial of Service) by passing a multi-byte character in the signature.
**Learning:** `string.length` is a character count, whereas `Buffer.length` is a byte count. When dealing with cryptographic functions that are strict about buffer byte lengths, comparing string lengths is insufficient and leads to unhandled exceptions with multi-byte input.
**Prevention:** Always instantiate the `Buffer` objects first, and compare their `.length` (byte length) before passing them to `timingSafeEqual`.
