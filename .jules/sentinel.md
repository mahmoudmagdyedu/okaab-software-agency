## 2024-05-18 - Prevent SSRF in Node.js URL resolution
**Vulnerability:** Node.js URL constructor evaluates paths starting with `//` or `/\` as protocol-relative URLs, leading to Server-Side Request Forgery (SSRF) when used with `new URL(path, base)`.
**Learning:** Path strings provided by user input must be sanitized before passing as the path segment in `new URL(path, base)` to prevent malicious domain redirection.
**Prevention:** Prevent SSRF by aggressively stripping leading slashes and backslashes (e.g., `path.replace(/^[/\\]+/, '')`) before URL construction.
## 2024-10-08 - [timingSafeEqual Length Check Vulnerability]
**Vulnerability:** The application was vulnerable to an unhandled exception (Denial of Service) when validating WebHook signatures. The validation function `validSignature` in `src/routes/api/youtube/webhook.ts` compared the lengths of the *strings* (`expected.length === supplied.length`) instead of the lengths of the instantiated `Buffer` objects, before passing them to `timingSafeEqual`. This could allow an attacker to send a signature containing multi-byte characters with the same string length but a different buffer byte length, causing Node.js to throw a "Input buffers must have the same byte length" error.
**Learning:** When using `crypto.timingSafeEqual` in Node.js, you must always compare the byte lengths of the instantiated `Buffer` objects, not the lengths of the original strings before Buffer conversion, to avoid unhandled exceptions, timing attacks, or DoS vulnerabilities when handling multi-byte characters (like UTF-8 defaults).
**Prevention:** Always check `buffer1.length === buffer2.length` directly on the buffers before calling `timingSafeEqual(buffer1, buffer2)`.
