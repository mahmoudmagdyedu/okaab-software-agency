## 2025-02-27 - Server-Side Request Forgery (SSRF) via Node.js URL parsing
**Vulnerability:** Found a Server-Side Request Forgery (SSRF) vulnerability in proxy functions within `src/server.ts`, `src/routes/__clerk/$.ts`, and `src/routes/clerk-proxy/$.ts`. The code appended a user-supplied path directly into a `new URL()` constructor alongside a base URL. In Node.js, if a user provides a path starting with `//` or `/\`, `new URL` parses it as a protocol-relative URL to the user's host, overriding the base URL entirely.
**Learning:** Node.js `new URL(path, base)` will discard the `base` origin if `path` starts with `//` or `/\`. Directly using substrings from `request.url` or `incomingUrl.pathname` without sanitization allows an attacker to construct paths like `//evil.com`, which the application will then unknowingly proxy requests to, leading to SSRF.
**Prevention:** Aggressively strip leading slashes and backslashes from user-provided paths (e.g., `path.replace(/^[/\\]+/, '')`) before concatenating them with a single slash and constructing a URL using `new URL(path, base)`. This prevents Node.js from evaluating the path as a protocol-relative URL.
