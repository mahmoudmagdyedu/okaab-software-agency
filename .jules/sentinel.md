## 2025-03-09 - [Timing Attack Vulnerability in Secret Comparison]
**Vulnerability:** The API endpoint `src/routes/api/internal/health/deep.ts` compared authentication secrets using simple string comparison (`!==`).
**Learning:** Standard string comparisons terminate early when a character mismatch occurs. This leaks timing information, which an attacker can use to brute-force the secret character by character in a timing attack. Additionally, when using `timingSafeEqual` with strings, it is crucial to convert the strings to buffers first and compare their `byteLength`, rather than their character `length`. This is because multi-byte characters (e.g. emojis) will cause matching character counts but differing byte lengths resulting in unhandled `TypeError` exceptions in Node.js when passed to `timingSafeEqual`.
**Prevention:** Always use constant-time comparisons like `crypto.timingSafeEqual` in Node.js when comparing passwords, API keys, or other authentication secrets. Always compare buffer `byteLength` prior to passing them to `timingSafeEqual` rather than string character length.
