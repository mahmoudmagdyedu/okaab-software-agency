## 2025-02-17 - [CRITICAL] Prevent DoS in `crypto.timingSafeEqual` with Multibyte Strings
**Vulnerability:** The signature validation logic in `validSignature` compared string `.length` before passing the strings to `Buffer.from()` and then `timingSafeEqual()`. If an attacker sent a signature string of the same length as the expected string but containing multi-byte characters (e.g. emojis or special chars), `Buffer.from()` produced a buffer with a different byte length. `timingSafeEqual` threw an unhandled `TypeError` because the byte lengths did not match, resulting in a 500 server crash and enabling a Denial of Service (DoS) attack.
**Learning:** `timingSafeEqual` requires the exact same *byte length* for its buffer inputs, which can differ from string length when multi-byte characters are used. A simple string `.length` comparison is not sufficient to guard against this exception.
**Prevention:** Always instantiate `Buffer` objects first, and then compare their byte lengths (`buffer.length`) before calling `timingSafeEqual`. This ensures that even if strings have the same character length but different byte lengths, the comparison safely returns false instead of crashing.
