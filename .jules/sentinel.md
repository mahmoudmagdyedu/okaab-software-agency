## 2024-05-15 - [CRITICAL] Prevent DoS in timingSafeEqual by checking Buffer lengths
**Vulnerability:** Comparing string lengths (`expected.length === supplied.length`) and then directly passing `Buffer.from(expected)` and `Buffer.from(supplied)` to `crypto.timingSafeEqual()`. If an attacker supplies a string with multi-byte characters, the string lengths could match while the buffer byte lengths differ. This causes `timingSafeEqual()` to throw an unhandled `TypeError`, crashing the Node.js process and resulting in a Denial of Service (DoS).
**Learning:** String length and buffer byte length can differ for multi-byte characters. `crypto.timingSafeEqual()` strictly requires `Buffer` objects of the exact same byte length and will throw synchronously if they are not.
**Prevention:** Always instantiate `Buffer` objects first, and then compare their lengths (`expectedBuffer.length === suppliedBuffer.length`) before calling `crypto.timingSafeEqual(expectedBuffer, suppliedBuffer)`.
